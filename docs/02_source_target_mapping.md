# Source-to-target mapping

Blueprint for the [v1.0 data contract](02_data_contract.md), [field dictionary](02_data_dictionary.md) and [DuckDB schema](../src/schema.sql). The frozen project specification owns financial recognition and metric formulas. This document maps fields and specifies where C should enforce the contract.

## Source intake and acquisition

| Inputs and keys | Target | Rule and exceptions |
|---|---|---|
| Source extract manifest, version and cutoffs | run_manifest.run_id, effective_cutoff, recorded_cutoff, source_manifest_hash, contract_version, build_version | Freeze source manifest and time cutoffs for each run. Treat effective completeness as exclusive and recorded availability as inclusive. Preserve deliveries and use exception_log for deferred or rejected rows, retaining source table, key, reason and details. |
| registration.registration_identity and visitor_identity → identity_link.identity_key | acquisition.customer_id, registration_id, registration_at, signup_date, signup_month | As of registration, evaluate effective and available identity claims after replaying retractions. Exclude void signup observations and unresolved identities from canonical signup counts, with reason-coded exceptions. Choose earliest valid registration per canonical customer, tie by registration ID. Resolve visitor linkage separately for attribution. |
| acquisition.registration_id → registration.visitor_identity → marketing_touch.visitor_identity → campaign.campaign_id | attribution.customer_id, touch_id, campaign_id, channel, status, rule_version, feature_cutoff | Select latest eligible touch inside the A window and available at signup. Tie by touch ID. Check campaign availability and channel, and require the visitor link to resolve to the acquired customer. Keep a canonical acquisition with no eligible touch, missing visitor linkage or ambiguous visitor linkage as UNKNOWN with null touch and campaign. Preserve original point-in-time result on replay. |
| registration_feature.registration_id → acquisition.registration_id; attribution.customer_id | feature_snapshot.feature_cutoff, channel, normalized_intent, feature_id, feature_available_at, input_status, snapshot_hash | Select eligible intent as of signup using the contract order. Late rows never supply the frozen feature value or pointer. Persist normalized channel and intent and source provenance for eligible inputs. Missing/invalid/late provenance and diagnostics must never change the acquisition-time scoring inputs after freeze. |
| feature_snapshot.customer_id × forecast_model.model_version | prediction.expected_365_cents, scored_at, written_at; prediction_age.age_days, expected_cents | Hash the immutable parameter payload and calculate A's product expectations at four horizons. Round the summed result once per age and ensure 365 matches the headline. EQUAL_CHANNEL references the BASELINE version and changes only multipliers. Join the exact same snapshots and compare on identical customer, age and spend populations. |

## Activity and the signed ledger

| Inputs and keys | Target | Rule and exceptions |
|---|---|---|
| product_activity_delivery.source_key / delivery_id, account_id → product_account.account_id; owner_identity → identity_link.identity_key → acquisition.customer_id | canonical_activity.run_id, source_key, delivery_id, account_id, customer_id, status | Restrict to records available at run cutoff and to effective events in scope. Collapse identical business payloads using earliest availability and stable delivery ID for ties. Quarantine conflicting payloads or invalid references. Resolve owner with effective identity at event time and recorded availability at the snapshot cutoff. Preserve accepted non-economic rows and unresolved owners for traceability. |
| canonical_activity delivery → product_activity_delivery activity_code, amount_cents, annual_rate, state and balance_kind | financial_event.source_key, component, account_id, customer_id, event_code, class, signed_cents, effective_at, recorded_at | Require valid code, product, state and bases per A and B. For direct components take source cents; for accrual components multiply balance cents by annual rate / 365 and round half-up to cents. Emit stable event ID from source key and component. Ordinary recognized amounts are positive in their class; unresolved owners and non-economic movements stay outside customer financial events. |
| ADJUSTMENT original_source_key and component → original financial_event within run | financial_event.original_event_id, adjustment_kind, class, signed_cents and event timestamps | Inherit target class, code and account. Negative signed amount reverses only the affected class. Restatements use original effective instant and correction availability. Later reductions and recoveries use their own effective and availability instants. Validate original availability, recognized amount remaining, linkage and processing order. Keep rejected adjustments in exception_log. |

| Product | Representative source → ledger mapping | Operational and exclusion rule |
|---|---|---|
| Savings | SAV_TREASURY_INCOME and SAV_DEPOSIT_INTEREST use their respective daily balance/rate bases. SAV_FEE → revenue; SAV_SERVICE → cost. | DEP_SETTLED in the frozen fixture is an external settled deposit and can activate under A. Deposit and withdrawal principal remain source-only. |
| Debit | DEBIT_INTERCHANGE → revenue; DEBIT_PROCESSING and DEBIT_REWARD → cost. Linked component reductions target the original row. | PURCHASE_SETTLED/PURCHASE_REFUND determine net purchase eligibility. Face values never enter the ledger. |
| Credit | CREDIT_INTERCHANGE and CREDIT_INTEREST → revenue; CREDIT_FUNDING and confirmed CREDIT_LOSS → cost. Recovery reduces the original loss cost. | Settled purchases support activation. Exclude purchase face value and repayments of principal. Realized losses use confirmed charge-offs and recoveries. |
| Personal loan | PERSONAL_INTEREST on performing principal and PERSONAL_FEE → revenue; PERSONAL_FUNDING and PERSONAL_SERVICE → cost. Fee correction can restate earlier accounting. | LOAN_FUNDING can activate. Funding, principal repayment and settlement of previously accrued interest are not new earnings. |
| Mortgage | MORTGAGE_INTEREST and MORTGAGE_FEE → revenue; MORTGAGE_FUNDING and MORTGAGE_ORIGINATION → cost. | Funding qualifies under A. Funded and repaid principal remain source-only. |

## Histories and reporting

| Inputs and joins | Target | Window, grain and metric behavior |
|---|---|---|
| canonical_activity → delivery and product_account; join adjustments by original source | activation.activation_at, source_key, status | Use A's qualifying source actions within the 30-day half-open customer window. Apply valid operational reductions available as of the run. At the customer grain OR product eligibility and count customer once. |
| acquisition × checkpoint, left join financial_event by run/customer | customer_age.horizon_end, maturity, revenue_cents, cost_cents, contribution_cents | Include qualifying effective events from signup up to but excluding horizon_end and available in the snapshot. Keep mature zero-activity customers, use null financials when pending, and sum signed revenue less signed costs. Preserve run and source pointers for replay. |
| campaign_day by campaign and spend date × winning-touch attribution joined via touch_id | spend_allocation.signup_month, spend_recorded_at, allocated_cents, winner_count, lag_incomplete | Select latest available source version. Calendar uses the original spend date month, produces null winner_count, and has no touch join dependency. Touch weighting allocates by winning-touch signup month with A's cents and no-winner treatment. Preserve spend-only rows. Reconcile each method separately at campaign-day and total levels. |
| acquisition + attribution grouped by channel/signup month × customer_age and prediction_age; independent spend_allocation rollup via campaign.channel | channel_cohort counts, spend, signed outcomes, forecast totals and ratios | Use consistent run, allocation, model and age keys. Retain unknown and spend-only groups, and distinguish pending maturity from zero activity. Compare realized and predicted on the same eligible group. Preserve A's 90-day revenue comparison as the designated ROAS series. Use summed exact cents and counts before division and round once to eight decimals, half-up. Spend-only CAC and ROAS are null with ZERO_DENOMINATOR and display as N/A. Preserve the spend in reconciliation. |
| campaign_day and applicable campaign_budget + acquisition/attribution via campaign_id and signup date; join activation and baseline prediction by customer | campaign_performance_day registrations, spend, activation counts, forecast totals, CAC, cumulative pacing and readiness | Build campaign-day rows including zero signups. Use latest available spend and plan versions. Roll up actual and plan over the relevant budget period, preserving missing plan and incomplete input states. Incomplete or missing plan coverage produces null plan_to_date_cents and pace_ratio plus UNAVAILABLE pacing. Never zero-fill plan inputs. Derive weekly review from aligned signups and spend. |

## Enforcement boundary

DDL enforces types, requiredness, keys, enumerations and simple row invariants. Transformations must enforce point-in-time references, latest-version selection, source code/product/state compatibility, run alignment, matching ownership, campaign and touch agreement, adjustment chronology and caps, exactly four trajectory ages and headline equality, immutable snapshots and model parity, complete-month maturity, traceability and reconciliation. Malformed physical input is captured and described before typed source insertion if it would violate schema constraints.
